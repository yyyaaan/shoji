# AGENTS.md — Shoji

Shoji is a native macOS app that hosts the user's terminal sessions ("threads") under a Liquid Glass card shelf. Every thread is the user's own shell: they `cd` anywhere and run coding-agent CLIs (`claude`, `codex`) or long-running commands (`docker compose up`, `pnpm dev`), and quit back to the prompt as usual. Shoji shows what's running and what needs the user. It is NOT an editor, diff viewer or file browser (the user keeps Zed / VS Code for those), and NOT an agent client: it never talks to models or APIs.

Words used everywhere (code, docs, chat): a **thread** is one hosted shell session, whatever runs in it; the **shelf** is the strip of **cards** across the top, one per thread in the user's order, with **bars** splitting it into groups that mean whatever the user wants; a **pane** shows a thread's terminal below the shelf; the **compact form** is the same window made narrow (Split View beside an editor): no shelf, one column of one or two panes; the **Hub** (planned) shows big cards. Mascot: **Hachi**, an Akita who appears on a card and in the window's corner when a thread needs the user.

**`PLAN.md` is the living state file.** Read its Status, Tasks and Gotchas before starting, then check `docs/handoffs/` for work addressed to you. Update Status and Tasks when you finish a session.

## Stack

- Swift 6 + SwiftUI, deployment target **macOS 26** (Liquid Glass: `.glassEffect()`, `GlassEffectContainer`).
- Terminal core: **SwiftTerm** (MIT, Swift package), pinned exactly in `project.yml`, Metal renderer.
- Project file generated by **XcodeGen** from `project.yml`; never hand-edit `.pbxproj`.
- No third-party packages besides SwiftTerm without asking first.

## Commands

```
xcodegen generate        # after any project.yml change and on a fresh clone (.xcodeproj is not committed)
xcodebuild -scheme Shoji -derivedDataPath build -destination 'platform=macOS' -skipPackagePluginValidation build
xcodebuild -scheme Shoji -derivedDataPath build -destination 'platform=macOS' -skipPackagePluginValidation test
open build/Build/Products/Debug/Shoji.app
scripts/package.sh [version]     # universal Release app + DMG, ad-hoc signed
# Releasing: bump MARKETING_VERSION in project.yml in a PR; merging it publishes vX.Y.Z (release.yml)
```

`-skipPackagePluginValidation` is needed because SwiftTerm runs a build-tool plugin; in Xcode, click Trust & Enable once instead. `main` is protected: work on a branch, one PR per change, green `test` check, squash merge. Debug builds are their own app (`fi.yan.shoji.debug`, Shoji Debug, own notifications and UserDefaults) and keep threads and socket in `~/Library/Application Support/Shoji-Debug`, so a dev build runs beside the installed one. If a command here is wrong or missing, fix this file in the same change.

## Hard invariants (do not break without the user's explicit OK)

1. **SwiftTerm is pinned** to an exact version. A bump is its own change and re-runs PLAN's terminal checklist.
2. **Only `Terminal/` imports SwiftTerm.** Everything else talks to `TerminalBackend`, so the engine stays swappable (libghostty is the fallback).
3. **Glass on chrome only.** Shelf, cards, pane headers, toasts and menus are glass. Terminal content sits on its own background: `Palette.paneOpacity` (80%) in panes with no blur, solid in the quick terminal and with Reduce Transparency.
4. **No tmux or any multiplexer.** Persistence is relaunching with the CLI's own resume (`claude --resume <id>`, `codex resume <id>`).
5. **One status path.** Every status change is a `StatusEvent` (from the socket, or terminal callbacks: title, bell, exit, the zsh integration's `OSC 1337 ; ShojiEvent=…` reports) applied by `ThreadStore` on the main actor. UI never derives status from terminal output.
6. **Never type into a terminal on the user's behalf** except through an explicit user action (e.g. Hub "Allow once"), sending exactly the keystroke the UI shows, and log it. Relaunching isn't typing: the zsh integration runs the resume at a restored shell's first prompt and leaves any other last command at the prompt for Return.
7. **Hooks must never slow or break the CLIs.** `shoji-hook` exits 0 within ~100 ms, silently when Shoji isn't running.
8. **Don't touch the user's global CLI config** (`~/.claude`, `~/.codex`) without an explicit opt-in. Inject per launch (env vars, a settings file, a config override), and verify current CLI flags before relying on them.
9. **`threads.json` is versioned.** Bump `schemaVersion` and add a migration only when another Shoji couldn't read the new shape; optional additions and ignored removals stay on the current version. Never silently drop a user's threads.

## Terminal setup rules

- Launch every thread as the user's **login shell** (`$SHELL -l -i`) so PATH and environment match a normal terminal.
- **zsh integration** (`scripts/shoji.zsh`): `ZDOTDIR` points at a `.zshenv` that restores the user's and sources it, so their dotfiles load unchanged. On the first prompt it adds precmd/preexec hooks and `claude` / `codex` functions that pass Shoji's hooks (`--settings`, `-c hooks={…}`). Other shells run without folder, command or agent status.
- **Scrollback** 10,000 lines (SwiftTerm's default is 500).
- **Shift+Return** sends ESC + CR (a newline in agent prompts) unless the program enabled the Kitty keyboard protocol.
- **Option as Meta** on, so Option shortcuts reach the CLIs.
- SwiftTerm delegate defaults can't be overridden: a **proxy `TerminalViewDelegate`** forwards every call (`docs/swiftterm.md`).
- "Needs you" comes from hooks via the socket, never from Claude Code's own desktop notifications (it only sends those in a few terminals).

## Conventions

- Swift 6 strict concurrency, no default actor isolation; `ThreadStore` and `TerminalSessions` are `@MainActor @Observable`. The thread model is `ShojiThread` (`Thread` would shadow Foundation's).
- Tests use Swift Testing; the test host runs the app headless (no shells, no socket; keep `ShojiApp.isHeadless` in sync). Suites follow features; `Support.swift` has `store.send(_:to:)` and `numberedThreads(_:)`. Extend a scenario before adding a near-duplicate test.
- To check UI by hand, launch the built app and use `screencapture -l <windowid>`; press controls with System Events `AXPress`, never keystrokes (they go to the user's frontmost app).
- **Sizes:** chrome metrics multiply by `@Environment(\.zoom)` (View › Interface Size). Terminal text is separate: `TextZoom` (⌘+ / ⌘−) plus a thread's `textSteps`.
- **Shortcuts** go in the `Shortcut` catalog (`App/Shortcuts.swift`), which feeds both the menus and the ⌘/ sheet. ⌘K is the quick terminal on purpose.
- Child processes get `SHOJI_THREAD_ID` and `SHOJI_SOCKET`; the zsh integration also reads `SHOJI_ZSH`, `SHOJI_USER_ZDOTDIR`, `SHOJI_CLAUDE_SETTINGS`, `SHOJI_CODEX_HOOKS`, `SHOJI_RESUME` and `SHOJI_PREFILL`. Inherited `SHOJI_*` variables are stripped first.
- Status is never colour-only: every state has its own shape and a text label.
- Every view gets a SwiftUI preview backed by `Threads/Mock.swift`.
- **Comments:** only the non-obvious why (a platform quirk, an invariant, a compatibility key), one line where possible. Behaviour, menu paths and decisions live in PLAN.md and the README.
- **Docs** describe the current state; history stays in git.
- Keep changes small; one task per PR when practical.

## Handoffs between agents

Agents (e.g. app and design) pass work through files in `docs/handoffs/`, which stay out of git because every agent shares this checkout.

- One file per handoff: `<yyyy-mm-dd>-<from>-to-<to>-<topic>.md`, roles `app`, `design`, `review` or `any`. Keep it short: what and why, links to what it relies on, a checklist of asks, how to tell it's done. Questions for the user go to PLAN.md Open questions.
- Claim a file addressed to you with `Taken by: <role>, <date>` at the top. Don't edit someone else's open handoff beyond claiming it or removing asks you finished.
- When done, move anything lasting to its home (PLAN.md, AGENTS.md, `docs/design/`) and delete the file in the same change; if only part is done, remove the finished asks.

## Design reference

`docs/design/` holds the accepted references (`threads-shelf.html`, `hub.html`, Hachi, status and completion artwork). Read the HTML for layout, spacing, radii and colours and translate it to SwiftUI; don't port the CSS literally. Status palette (dark UI):

| State | Color | Icon |
|---|---|---|
| Working | `#74B8FF` | spinning arc |
| Needs you | `#FF9F43` | ring + "!", card glow, count badge, Hachi |
| Done | `#E2E8F0` | check |
| Idle | `#E2E8F0` at 55% | Torii gate (`docs/design/status/`) |
| Running | `#4FD1B5` | pulsing dot |
| Exited / error | `#FF8787` | ring + × |

Terminal background `#0C0F15`; UI type SF Pro; terminal font the monospaced system font, 13 pt × text size.

## Don't

- Don't add an editor, diff view, file tree or git UI.
- Don't call model APIs or embed agent SDKs.
- Don't put glass or blur behind terminal text, or take a pane's background below `Palette.paneOpacity`.
- Don't parse terminal output for status (invariant 5).
- Don't hand-edit `.pbxproj`.
- Don't change an invariant without asking; propose it in PLAN.md Open questions.
